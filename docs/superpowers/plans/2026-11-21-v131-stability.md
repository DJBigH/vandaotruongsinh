# 1.3.1 Loading and Interaction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make game loading measurable and recoverable while correcting mount navigation.

**Architecture:** A pure manifest selector determines boot and map assets. Phaser loads the first set at boot and the second set in the map fetch path, before rendering. The game page displays status from the data loaders and scene. The health endpoint probes PostgreSQL.

**Tech Stack:** TypeScript, React, Phaser 3, Fastify, Prisma, Node test runner.

**Spec:** `docs/superpowers/specs/2026-11-21-v131-stability-design.md`

## Global Constraints

- Patch version `1.3.1`; preserve saves, odds, and all existing PNGs.
- Push only to `version-1`, and keep its local checkout in sync. Do not update `main`.

## Review Focus

- Asset load failure must not start a partially rendered world.
- Portal transitions must load destination bosses and region art before rendering.
- An event boss and equipped mount must keep their animation textures.
- A valid character with a failing inventory/quest request must see retry rather than create-character.
- A mount in a different region must never receive a remote tame request from the panel.
