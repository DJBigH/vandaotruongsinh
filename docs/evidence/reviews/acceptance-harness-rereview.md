## New Important findings

- **Commands submitted during finalization can wait for a result that this session will never publish.** `play-session.mjs:197–203` stops the consumer immediately, and `:228` closes `ready.json` only after finalization. `send-command.mjs:12–22` can therefore accept a command under an active-looking session ID during the wait for context close or ffprobe. A command queued behind `finish` before intake stopped has the same outcome. Publish the closing state when `finish` is dequeued and return a terminal rejection for pending requests, or make the sender detect session closure while waiting and report a terminal result when its request remains unprocessed. Sequential senders that treat `finish` as the final action avoid this race.
- **The frozen artifact hash and the source stamp represent different events.** `frozen-preview.mjs:7–16` asserts that a previous `client/dist/index.html` exists, then records the current source stamp at copy time. An older successful build can therefore be attributed to a newer checkout if the build-first step is missed. Record the source stamp from the successful build, or label the copy-time stamp explicitly and support final attribution with the fresh build command and its result. The file hash itself identifies exactly what was served.

No new Critical issue found. Runtime load and recorded journey conclusions remain with the controller's actual run outputs.

## Final scoped verdict

- **Shutdown queue addressed.** `play-session.mjs:197–204` publishes `closing` immediately when `finish` is dequeued. `send-command.mjs:12–29` rejects new closing submissions and terminates the wait for an unprocessed request once the session closes. `play-session.mjs:219–231` finalizes and probes the recording, publishes the manifest and atomically publishes the finish result before marking the session closed. The sender rechecks the result after observing closure, so it can still consume a concurrently published finish result.
- **Frozen-build provenance addressed for the controller's serialized builds.** `frozen-preview.mjs:8–23` runs the production build, compares the source stamp before and after, and hashes the actual copy served by both entry points. `evidence-utils.mjs:12–23` includes the public assets, HTML and build configuration and hashes the contents of changed and untracked files in scope, including binaries. The scripts still share `client/dist` as a build destination, so this result assumes the controller does not run competing builds during the freeze.
- **E2 instrumentation addressed.** `focus-probe.mjs:21–35` records position before foreground activation, keeps the key held through the stale-motion observation and requires a new foreground TICK. It also requires zero INPUT messages over the measured background window, including neutral packets counted at `browser-helpers.mjs:73–79`. Sustained background TICKs are outside the acceptance condition because the server's five-second silence timeout intentionally pauses simulation. A headless run that observes no focus loss remains inconclusive.
